# 10분 최종 보스 발견성 개선 계획

> 상태: 구현 전
>
> 목표: 자동 테스트를 새로 만들지 않고, 일반 10분 런을 직접 플레이해 보스의 출현·추적·HUD 체감을 확인하며 조정한다.

## 1. 작업 정의

| 항목 | 내용 |
| --- | --- |
| 유형 | 보스 조우 버그 수정 + UI/UX 개선 |
| 크기 | 짧은 구현·실플레이 조정 루프 |
| 위험 | 중간. 생성 위치와 원거리 이동만 바꾸고 근접 전투 밸런스는 유지해야 한다. |
| 데이터/저장 | 변경 없음 |
| 의존성 | 변경 없음 |
| 자동 테스트 | 새 테스트를 추가하거나 기존 테스트를 삭제·수정하지 않는다. |

### 완료 목표

- 일반 모드의 600초 경계에서 최종 보스가 카메라 안이면서 상단 HUD에
  가려지지 않는 위치에 한 번만 출현한다.
- 출현 순간 기존 알림과 함께 HUD가 `FINAL BOSS`를 명확하게 표시한다.
- 미니보스가 살아 있어도 최종 보스가 출현한 뒤에는 최종 보스 체력바가 우선한다.
- 최종 보스가 화면 밖으로 나가면 방향을 알 수 있고, 플레이어가 계속 도망쳐도 영구적으로 유실되지 않는다.
- 카운트다운은 실제 600초 경계 전에 `00:00`을 표시하지 않는다.
- 일시정지, 일반 적 생성, 미니보스, 최종 보스 HP·공격·보상·승리 조건은 그대로 유지한다.

### 제외 범위

- 고정 timestep 또는 벽시계 기반 타이머로 전환
- 전체 적 이동속도 재조정
- 최종 보스 기본 데이터 속도 `70`의 일괄 배수 증가
- `SpawnDirector`의 300초·600초 출현 규칙 변경
- 테스트 브리지, E2E 시간, 테스트 파일 변경
- `SurvivorScene`의 광범위한 리팩터링
- 새 패키지 설치

## 2. 현재 확인된 문제

### 2.1 `BOSS SIGNAL`은 최종 보스 전용 표시가 아니다

`GameHud.vue`의 `BOSS SIGNAL`은 현재 활성 상태인 `boss: true` 적 하나의
체력을 표시한다. `miniBoss`와 `finalBoss`가 모두 `boss: true`이므로
5분 미니보스와 10분 최종 보스를 화면에서 구분할 수 없다.

실제 플레이 화면에서도 미니보스 전투 중 상단에 이름 없는
`BOSS SIGNAL` 체력바가 표시되는 것을 확인했다. 이 표시는 최종 보스
출현을 뜻하지 않는다. 확인 화면의 상단 중앙에 보이는 갈색 왕관형 적은
`miniBoss` 스프라이트이며, 10분 최종 보스는 보라색·남색의 뿔 달린
별도 스프라이트다.

또한 `SurvivorScene.emitHud()`가 적 배열에서 처음 발견한 보스를 선택한다.
미니보스가 먼저 생성되어 살아 있으면 600초에 최종 보스가 출현해도
상단 HUD는 계속 미니보스 HP를 표시할 수 있다.

확인 화면에서는 미니보스 일부가 상단 체력바 뒤에 가려져 있다. 따라서
보스 중심점이 단순히 `camera.worldView` 안에 있는지만 확인해서는 실제
가시성을 보장할 수 없다. 상단 Vue HUD가 덮는 화면 영역까지 제외해야 한다.

### 2.2 최종 보스가 일반 적 위치 선택을 사용한다

`updateSpawning()`은 최종 보스도 `spawnEnemy('finalBoss')`로 생성한다.
현재 일반 생성 위치는 플레이어 기준 임의 각도이며, 화면 크기에서 계산한
반경에 추가 여백을 더한다. 실제 카메라의 추적 지연, 줌, 현재
`worldView`는 사용하지 않으므로 최종 보스 출현을 화면에서 바로 확인할 수
없다.

### 2.3 최종 보스는 플레이어를 따라잡을 수 없다

- 최종 보스 기본 이동속도: `70`
- 캐릭터 기본 이동속도: `164`~`204`
- 최고속도 캐릭터가 이동속도 패시브 5레벨을 얻은 경우: `204 × 1.5 = 306`

보스 기본속도를 단순히 4배로 올려도 `280`이라 최고속도 플레이어보다
느리다. 현재 보스는 플레이어와 2,200px 이상 멀어져도 일반 적처럼
비활성화되지 않으므로, 살아 있지만 보이지 않는 상태로 남을 수 있다.

### 2.4 카운트다운이 최대 약 1초 먼저 `00:00`이 된다

HUD의 남은 시간은 실수이지만 `formatClock()`이 내림 처리한다.
남은 시간이 `0.999`초인 동안에도 `00:00`이 표시되며, 최종 보스는
실제 경과시간이 600초 이상이 된 프레임에서 생성된다.

## 3. 대상 도메인과 SSOT

```text
Entities:
  Player, MiniBoss, FinalBoss, CameraWorldView, BossSafeView, BossHud

Key states:
  Player = position, velocity, facingAngle, effectiveMoveSpeed
  FinalBoss = active, position, hp, attackTimer
  BossEncounter = outOfRangeDuration, warningDelay, repositionCooldown
  BossHud = selectedBossId, hp, maxHp, offscreen, direction

Relationships:
  SpawnDirector → 600초에 FinalBoss 생성 요청을 한 번 발행
  SurvivorScene → FinalBoss 런타임과 조우 보정 상태 소유
  CameraWorldView → 현재 카메라가 렌더링하는 월드 영역
  BossSafeView → HUD 가림과 보스 반경을 제외한 실제 가시 영역
  HudSnapshot → Scene 상태에서 파생된 읽기 전용 값

Actions:
  600초 도달 → 카메라 안 생성 → 알림과 FinalBoss HUD 노출
  화면 밖 이탈 → 추적속도 보정 → 화면 안 복귀 시 기본속도 복원
  지속적인 원거리 유실 → 경고 → 전방 재배치 → 공격 유예

SSOT:
  출현 여부는 SpawnDirector, 경과시간·플레이어·적 상태는 SurvivorScene,
  카메라 영역은 camera.worldView가 소유하고, BossSafeView는 여기에서
  HUD의 화면 공간 점유와 보스 반경을 제외해 매 프레임 파생한다.
```

보스 위치·HP를 HUD나 별도 조우 상태에 복제하지 않는다. 조우 상태는 최종
보스 엔티티 ID와 경고·쿨다운 타이머만 보유하고, 실제 위치와 HP는 기존
`EnemyRuntime`을 참조한다.

## 4. 실제 수정 범위

### 4.1 최종 보스 전용 가시 영역 생성

`updateSpawning()`의 최종 보스 분기만 전용 위치 선택을 사용한다.
일반 적과 미니보스의 현재 생성 방식은 변경하지 않는다.

구현 원칙:

1. 실제 `camera.worldView`를 읽는다.
2. 상단 게임 HUD와 보스 체력바가 덮는 높이를 화면 공간에서 제외하고,
   이를 카메라 줌에 맞는 월드 좌표로 변환한다. 좌우·하단도 보스 반경과
   가장자리 여백만큼 줄여 `BossSafeView`를 만든다.
3. 플레이어가 움직이는 중이면 현재 속도 방향을, 정지 중이면
   `player.facingAngle`을 전방으로 사용한다.
4. 전방의 안전영역 가장자리 근처에서 플레이어와 가장 멀고 완전히 보이는
   지점을 선택한다.
5. 좁은 화면에서 전방 지점이 플레이어와 너무 가까우면 전방 반평면의
   다른 가장자리 지점 중 거리가 가장 먼 곳을 사용한다.
6. 생성 직후 공격이 불공정하게 시작되지 않도록 `attackTimer`에 짧은
   유예를 보장한다.

상단 HUD 안전 여백은 화면 기준 약 `120px`, 나머지 가장자리 여백은
보스 반경에 `24px`을 더한 값으로 시작한다. 이 값은 고정된 보스 생성
거리가 아니라 실제 HUD 점유 영역을 피하기 위한 초기 조정값이며, 모바일
비율 실플레이 결과에 따라 조정한다.

고정 `460px`, `scale.width / 2`, 단순한 `worldView.contains()`만
기준으로 삼지 않는다. 카메라는 부드럽게 플레이어를 추적하고 Vue HUD는
캔버스 위를 덮으므로, 플레이어가 화면 중앙에 있거나 카메라 안의 모든
지점이 실제로 보인다고 가정하면 안 된다.

적 런타임 생성 코드는 중복하지 않는다. 기존 `spawnEnemy()`에서 위치
선택과 런타임 생성을 작게 분리해, 일반 생성과 최종 보스 전용 생성이 같은
생성 본체를 호출하도록 한다.

### 4.2 화면 밖 추적속도 보정

최종 보스의 근거리 전투 동작과 기본속도 `70`은 유지한다. 보스가 현재
`BossSafeView` 밖에 있을 때만 다음 속도를 사용한다.

```text
effectivePlayerSpeed =
  player.moveSpeed × abilities.globalModifiers().moveSpeed

offscreenBossSpeed =
  max(finalBoss.definition.speed, effectivePlayerSpeed + catchUpMargin)
```

`catchUpMargin` 초기값은 `80`으로 시작하고 실플레이에서 재조우 시간을
보고 조정한다. 보스가 다시 화면 안으로 들어오면 즉시 기존 AI 속도로
복귀한다. 따라서 실제 교전 중 공격 간격이나 회피 난이도는 가능한 한
바꾸지 않는다.

### 4.3 원거리 재배치는 최후 안전장치로 적용

속도 보정만으로 실제 플레이에서 안정적으로 다시 만날 수 있으면
재배치를 과도하게 반복하지 않는다. 다음 조건이 모두 성립할 때만
재배치한다.

- 최종 보스와 플레이어 거리가 현재 카메라 대각선의 약 `1.5배`보다 멀다.
- 이 상태가 약 `2초` 이상 계속된다.
- 이전 재배치 쿨다운이 끝났다.

재배치 순서:

1. `최종 보스 신호 재포착` 알림을 표시한다.
2. 약 `0.8초`의 경고 시간을 둔다.
3. 4.1과 같은 전방 가시 영역 위치로 이동한다.
4. 기존 HP, 상태효과, 처치 상태는 그대로 유지한다.
5. knockback을 초기화하고 공격 타이머를 최소 `1.2초` 확보한다.
6. 약 `8초`의 재배치 쿨다운을 적용한다.

경고 중 보스가 안전 거리 안으로 돌아오면 불필요한 재배치를 취소한다.
거리 진입·이탈 기준에는 여유를 두어 경계에서 경고가 반복되지 않게 한다.

### 4.4 HUD에서 미니보스와 최종 보스 구분

`emitHud()`의 대상 선택 우선순위를 다음처럼 바꾼다.

```text
active finalBoss ?? active miniBoss ?? null
```

`HudSnapshot`에는 표시 문자열 대신 다음 의미 값을 추가한다.

```text
bossId: 'miniBoss' | 'finalBoss' | null
bossOffscreen: boolean
bossDirectionRadians: number | null
```

UI 동작:

- 미니보스: `MINI BOSS`
- 최종 보스: `FINAL BOSS`
- 한국어 UI에서는 각각 `미니보스`, `최종 보스`로 표시
- 선택된 보스가 `BossSafeView` 밖이면 체력바에 방향 화살표를 표시
- 카메라 안이더라도 상단 HUD 뒤에 가려진 보스는 화면 밖과 동일하게 취급
- 화살표는 보스의 월드 방향을 가리키되 보스가 화면 안에 들어오면 숨김
- progressbar의 접근성 이름에도 현재 보스 종류를 포함
- 데스크톱과 모바일 HUD 폭에서 이름·HP·화살표가 겹치지 않게 조정

현재의 모호한 `BOSS SIGNAL`만 단독으로 표시하지 않는다.

### 4.5 카운트다운 표시만 올림 처리

`GameHud.vue`에서 남은 시간을 표시할 때만 `Math.ceil()`을 적용한다.

```text
formatClock(Math.ceil(remainingSeconds))
```

공용 `formatClock()`과 결과 화면의 실제 경과시간 표시는 바꾸지 않는다.

## 6. 구현 순서

1. 최종 보스 위치 선택과 기존 적 생성 본체를 분리한다.
2. 600초 최종 보스 분기만 카메라 내부 전방 생성으로 연결한다.
3. 화면 밖에서만 유효한 추적속도 보정을 추가한다.
4. HUD의 최종 보스 우선순위와 미니/최종 보스 구분을 추가한다.
5. 화면 밖 방향 표시와 카운트다운 올림을 적용한다.
6. 정적 타입 검사와 번들 생성을 통과시킨다.
7. 테스트용 시간 단축 없이 일반 10분 런을 직접 플레이한다.
8. 실제 재조우 시간과 불공정 공격 여부를 기록하고 보정 상수만 조정한다.
9. 속도 보정으로도 보스가 유실될 때만 경고 후 재배치 안전장치를
   활성화하거나 임계값을 조정한다.

## 7. 실제 플레이 검증

자동화된 보스 테스트로 체감을 대신하지 않는다. 최소 한 번은 `e2e`
쿼리나 시간 조작 없이 일반 런을 600초 이상 직접 플레이한다.

### 실행 전 정적 확인

```bash
npm run typecheck
npm run build:bundle
```

이 두 명령은 컴파일 가능성만 확인하며 보스 조우 품질을 증명하지 않는다.

### 일반 10분 런 체크리스트

1. 일반 URL에서 가장 빠른 캐릭터인 `purple`로 런을 시작한다.
2. 이동속도 강화가 나오면 우선 선택하고, 가능하면 미니보스를 살려 둔다.
3. 600초 전에는 최종 보스와 `FINAL BOSS` HUD가 나타나지 않는지 본다.
4. 마지막 1초 동안 `00:01`이 유지되고 실제 경계에서 `00:00`이 되는지 본다.
5. 600초에 최종 보스 전체가 상단 HUD에 가리지 않고 보이며 출현 알림이 나타나는지 본다.
6. 미니보스가 살아 있어도 상단 체력바가 최종 보스로 전환되는지 본다.
7. 최종 보스 반대 방향으로 계속 이동해 일부러 화면 밖으로 보낸다.
8. 방향 화살표가 실제 보스 방향을 가리키는지 확인한다.
9. 보스가 화면 밖에서 플레이어를 따라잡아 다시 보이기까지 걸린 시간을 잰다.
10. 경고 후 재배치가 발생하면 순간 피격, 연속 재배치, 위치 깜박임이 없는지 본다.
11. 교전 거리 안에서는 기존 속도와 공격 패턴으로 돌아오는지 본다.
12. 플레이 중 창을 좁은 모바일 비율로 바꿔 HUD와 방향 표시가 겹치지 않는지 본다.
13. 최종 보스를 처치해 기존 승리, 코인 보상, 결과 화면이 정상인지 확인한다.

## 8. 중단 조건

다음 중 하나가 발생하면 수치 조정을 계속하지 않고 원인을 먼저 고친다.

- 최종 보스가 600초에 생성되지 않거나 두 번 이상 생성됨
- 생성 위치가 `BossSafeView` 밖이거나 상단 HUD에 가려짐
- 일반 적 또는 미니보스의 생성 위치가 함께 변경됨
- 화면 밖 보정 속도가 교전 중에도 적용되어 보스 난이도가 크게 바뀜
- 재배치가 HP·상태효과를 초기화하거나 보스를 새로 생성함
- HUD 변경이 모바일 조작이나 상단 상태 표시를 가림
- 일시정지 중 조우 타이머가 진행됨
